# XMEye Downloader

[English](README.md) | **Русский**

Небольшая программа с окном для Windows, которая скачивает записи с регистраторов **XMEye / Xiongmai** (DVR, NVR, HVR) по сети. Она работает по родному протоколу устройства (DVRIP «Sofia», TCP-порт **34567**), поэтому не нужны ни программа производителя, ни веб-плагин, ни снятие диска из регистратора.

Задаёшь период и каналы, и программа параллельно скачивает все записи за этот период. Видно, что качается и с какой скоростью. Записи можно сразу перепаковать в MP4 без перекодирования.

## Возможности

- **Поиск записей по периоду и каналам.** Регистратор опрашивается по одному дню, поэтому длинный период не обрезается лимитом на количество результатов одного поиска.
- **Параллельное скачивание.** Число потоков задаётся (1–32). У каждого потока своё соединение, файлы берутся из общей очереди.
- **Прогресс в реальном времени.** У каждого файла видны поток, процент, размер и скорость. В общей строке видны общий прогресс, скорость и оставшееся время, оно считается по последним 20 секундам.
- **Можно останавливать и перезапускать.** Файл пишется как `.part` и переименовывается только после полного скачивания. Готовые файлы при повторном запуске пропускаются.
- **Повторы при сбоях.** Упавший файл скачивается ещё 3 раза. Если не вышло, он помечается ошибкой, а остальные качаются дальше.
- **Лимит сессий.** Если регистратор не пускает столько сессий, лишние потоки отключаются, а их файлы докачивают остальные.
- **Конвертация в MP4 (по желанию, нужен ffmpeg).** Служебные заголовки Xiongmai вырезаются, и видео перепаковывается с правильным кодеком (H.264 или H.265) и частотой кадров. Ничего не перекодируется.
- **Удаление исходного `.h264` по желанию.** Удаляется только после того, как MP4 собрался и прошёл проверку размера.

## Что нужно

- Windows (проверено на Windows 11)
- [Python](https://www.python.org/downloads/) 3.9 или новее, с tkinter (он входит в стандартный установщик для Windows)
- [ffmpeg](https://ffmpeg.org/) в `PATH`. Нужен только для конвертации в MP4 (например, `winget install ffmpeg`).

Сторонние Python-пакеты не нужны.

## Как пользоваться

1. Запусти `Запуск.bat` двойным кликом (или `pythonw XMEyeDownloader.pyw`).
2. Введи IP регистратора, порт (по умолчанию 34567), логин и пароль и нажми **Подключиться**. Появятся галочки каналов.
3. Укажи период в полях **С / По** в формате `ДД.ММ.ГГГГ ЧЧ:ММ` и нажми **Найти записи**. Появится список файлов с размерами.
4. Выбери папку и число **потоков**, затем нажми **Скачать всё** или **Скачать выделенное**.

Настройки, кроме пароля, сохраняются в `settings.json` рядом с программой.

### Куда сохраняется

```
<папка>/
  канал01/
    2026-09-16/
      2026-09-16_14.00.00-15.00.00.h264
      2026-09-16_14.00.00-15.00.00.mp4
  канал02/
  ...
```

### Что будет при перезапуске

| Что уже лежит в папке          | Что сделает программа           |
|--------------------------------|---------------------------------|
| `.mp4`                         | пропустит                       |
| `.h264` без `.mp4`             | только поставит в очередь на MP4 |
| `.part` (прерванное скачивание) | скачает файл заново с начала    |
| ничего                         | скачает                         |

Проверка идёт по пути к файлу, поэтому между запусками папка должна быть та же.

## Скорость

Регистраторы ограничивают скорость **одного потока воспроизведения**: на устройстве, под которое писалась программа, это около 0,9 МБ/с. Общая скорость растёт почти пропорционально числу потоков (8 потоков дали около 6,5 МБ/с). Сколько одновременных сессий пустит регистратор, зависит от модели и прошивки. Если поставить слишком много, лишние потоки отключатся, и в логе появится строка об этом.

Один файл всегда качается одним потоком, потому что регистратор отдаёт файл одним последовательным потоком.

## Если что-то не так

| Сообщение / код                     | Что значит                                                                                |
|-------------------------------------|-------------------------------------------------------------------------------------------|
| `[203]` / `[106]`                   | неверный пароль или логин                                                                 |
| `[205]`                             | регистратор заблокировал IP после нескольких неверных паролей. Подожди ~30 минут или перезагрузи его по питанию. |
| `регистратор не отвечает (таймаут)` | проблемы с сетью или регистратор перегружен. Файл повторится автоматически.               |
| MP4 не получился                    | исходный `.h264` остаётся, его можно открыть в VLC                                        |

При каждом запуске рядом с программой пишется лог протокола `dvr_debug.log`. В нём служебные пакеты и первые байты каждого потока. Если регистратор ведёт себя странно, смотреть в первую очередь туда.

## Как устроен протокол

- **Логин** — сообщение 1000 с хешем пароля «Sofia» на основе MD5. **Поиск файлов** — 1440 (`OPFileQuery`): за один запрос приходит не больше 64 записей, следующая страница запрашивается от `BeginTime` последней. **Скачивание** — 1424 `Claim`, затем 1420 `DownloadStart`, затем поток пакетов 1426 до пустого пакета, затем 1420 `DownloadStop`.
- Одни прошивки отвечают на `DownloadStart` JSON-ом, другие сразу шлют видео прямо в ответном пакете. Программа понимает оба варианта.
- Скачанный `.h264` — это приватный контейнер Xiongmai, а не «сырой» видеопоток:
  - `00 00 01 FC` — I-кадр с 16-байтным заголовком: кодек (2 = H.264, 3 = H.265), fps, ширина/8, высота/8, время, длина.
  - `00 00 01 FD` — P-кадр с 8-байтным заголовком.
  - `00 00 01 FA` и `F9` — звук и служебная информация.

  Несмотря на расширение, видео часто в **H.265**.
